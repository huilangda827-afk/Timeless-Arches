## 一、项目背景

### 1.1 我们想解决什么问题

中国古建筑里有一种叫**斗拱**的构件 —— 它是榫卯木构的灵魂，承担屋顶重量、装饰飞檐、体现等级礼制。但是：

- **太抽象**：黑白结构图看了也不懂力流
- **摸不着**：博物馆隔着玻璃罩，村野古建不能动
- **学不会**：《营造法式》《工程做法》古籍读不懂

**结果**：年轻人对斗拱的认知，停留在"那个屋檐下方方正正的小木头"。

### 1.2 我们怎么解决

> 用 **Web + 普通摄像头 + 手势识别**，把"看不见摸不着"的斗拱变成"指尖可拼"

零硬件门槛 + 零下载安装 + 零专业知识 → 5 分钟体验一栋千年古建。

### 1.3 大赛背景

第 19 届中国大学生计算机设计大赛（4C，2026）  
主题：中国古代建筑成就（民居 / 官府 / 皇宫 / 桥梁，1911 前）  
赛道建议：数字媒体游戏与交互设计 · 交互媒体设计组

## 三、技术栈选型与原因

### 3.1 为什么用 Three.js 而不是 Unity / Unreal？


| 对比项       | Three.js (我们) | Unity WebGL     | Unreal Pixel Streaming |
| --------- | ------------- | --------------- | ---------------------- |
| 包大小       | ~600KB（精简后）   | 30 - 100 MB     | 需要服务器渲染                |
| 浏览器兼容     | 99% 现代浏览器     | 90%（WebGL 2 必需） | 需高性能服务器                |
| 学习曲线      | JS 即可         | C# + 引擎概念       | C++ + 引擎               |
| 中华文化项目契合度 | 轻量 / 普及       | 重 / 工业          | 重 / 工业                 |


→ **结论**：大赛主题是"中华文化普及"，**轻量 + 零安装** 是核心价值，Three.js 完胜。

### 3.2 为什么用 MediaPipe Hands？

- ✅ Google 开源，工业级稳定
- ✅ **浏览器端运行**，零后端
- ✅ 准确率 95%+（21 个手部关键点）
- ✅ CPU 即可，不需要 GPU 加速
- ❌ 唯一缺点：手势库需要自己写（捏合 / 张开 / 移动），但本项目交互单一，可控

### 3.3 为什么用 Vite？

- 🚀 **冷启动 < 1 秒**（vs webpack 5 - 30 秒）
- 📦 **ES Module 原生支持** —— 写 `import { foo } from './bar.js'` 即可
- 🔥 **HMR 极快** —— 改一行代码，浏览器立刻更新
- 🛠️ **零配置 multi-page**：在 `vite.config.js` 加 `input` 字段即可

### 3.4 自研校准工具（calibrator.html）

> 这是项目中最重要的工程亮点之一，建议在 PPT 单独说

**问题**：每个新建筑要标定每根构件的精确目标位置（XYZ + 旋转 + 缩放），手工写 JSON 几乎不可能。

**我们的方案**：

- 浏览器端可视化工具：左侧 3D 场景 + 右侧滑条
- 美术师拖动 / 旋转 / 缩放 → 实时看到效果
- 一键导出 JSON：`targetOverrides` / `dockOverrides` / `environmentTransform`...
- 程序员复制 JSON 到 `LEVELS[]` → 新关卡 5 分钟上线

→ **未来扩展 50 个建筑，无需改一行代码**

## 四、5 个核心模块详解

### 4.1 门户首页（index.html）

**视觉**：原始美工产出的高保真 mockup（米黄古风 + 5 张主功能卡）

**技术**：

- 一张大 base64 PNG 作背景（保留美工原视觉）
- "热区"div 叠在 PNG 上接收点击
- 路由切换 = 换 PNG

**为什么这样做**：

1. 保留美工 100% 视觉精度
2. 不需要重写整套 HTML/CSS（mockup 是 AI 生成的，重写会丢风格）
3. 后期可逐步把 PNG 替换为真实 DOM（已经在鉴赏页这么做了）

### 4.2 万象图鉴

**功能**：所有可探索建筑的总目录

- 上半屏：6 张原 AI 风格化封面（应县木塔 / 佛光寺 / 太和殿 / 赵州桥 / 晋祠 / 岳阳楼）
- 下半屏：9 张真实古建图片卡（含元殿 / 万春亭 / 平遥县衙 ……）
- 顶部：搜索框（按建筑名 / 朝代 / 地区）
- 整页可滚动

### 4.3 鉴赏（核心）

**入口**：万象 / 首页鉴赏卡 / 古建舆图点位

**单页结构**：

```

│   [3D Three.js]        │ 明代（1536）· 紫禁城   │
│   左键拖拽旋转          │ ─────────────────     │
│   滚轮缩放              │ 建筑背景              │
│   右键平移              │ ……                   │
```

**实现要点**：

- 独立 three.js scene + OrbitControls（不与主游戏冲突）
- 每次打开新建筑时 dispose 旧模型
- 模型自动归一化到 6 米直径，相机自适应距离

### 4.4 探微（核心 · 教育价值高）

**入口**：鉴赏浮层 → "进入探微" / 顶部 NAV "探微"

**功能**：

- 加载万春亭 6 个组件集合（撩檐榑组 / 乳栿组 ……）
- "整体" 模式 = 全部组装好显示
- "一键解体" = 6 个集合按"幽灵参考位置 → 向外辐射 1.5m"动画散开
- hover 单个集合 → 金色发光高亮 + 显示集合中文名
- 点击集合 → 弹出右侧介绍卡：集合中文名 + 包含的所有部件名 + 力学/装饰解析

**部件命名（重要）**：

```
集合壹（屋檐顶层）：撩檐榑 + 压槽枋 + 罗汉枋 + 替木
集合贰（横向梁系统）：乳栿 + 耍头里转 + 齐心斗 + 蚂蚱头 + 耍头 + 慢拱 + 令拱
集合叁（柱头铺作）：柱头枋 + 㭼头 + 交互斗（隔口包耳）+ 琴面昂（下折假昂）+ 瓜子拱
集合肆（外檐铺作）：柱头枋 + 琴面昂 + 散斗 + 交互斗
集合伍（基础斗与拉接）：泥道拱 + 栌斗（四耳栌斗）+ 阑额 + 普拍枋
集合陆：木栓
```

### 4.5 筑梦（最强游戏属性）

**入口**：从首页 / 万象 / 鉴赏浮层 跳转 forge.html

**核心循环**：

1. 玩家看到备料架上 6 个斗拱构件 + 半透明"幽灵"目标位
2. 拇指食指捏合 → 抓起最近构件
3. 移动手部 → 构件跟随
4. 接近目标位 → 自动磁吸预对齐
5. 松开手 → 自动判定吸附（位置 + 角度都对就 ✅）
6. 全部 6 个完成 → 摄像机绕飞 + 金色粒子庆祝

**关键算法 - 三阶段磁吸**：

```javascript
const dist = piece.distanceTo(target);
if (dist > 1.5) {
  // 远距离：完全跟随光标，自由把玩
  piece.position.copy(cursor);
} else if (dist > 0.2) {
  // 中距离：位置/旋转/缩放 smoothstep 向 target 插值
  const t = smoothstep(0.2, 1.5, dist);  // 越近 t 越小
  piece.position.lerpVectors(target, cursor, t);
  piece.quaternion.slerpQuaternions(target, freeQuaternion, t);
} else {
  // 近距离：直接锁到 target，松手就吸附
  piece.position.copy(target);
  piece.quaternion.copy(target.quaternion);
}
```

→ **效果**：手势识别有抖动，但用户感受是"被磁石吸住"

## 五、数据驱动：LEVELS 数组

`src/main.js` 里有一个 `LEVELS` 数组，每项是一个关卡：

```javascript
const LEVELS = [
  {
    id: 1,
    name: '入门 · 单翘斗拱',
    pieceNames: ['大斗', '华拱', '正心瓜拱', ...],
    pieceLore: { 大斗: { brief: '...' }, ... },
    targetOverrides: { 大斗: { position: {...}, quaternion: {...} } },
    cameraPos: { x: 6, y: 4, z: 6 },
    ...
  },
  {
    id: 2,
    name: '北京紫禁城御花园万春亭',
    pieceNames: ['集合壹', '集合贰', ..., '集合陆'],
    ...
  },
];
```

**新增关卡的步骤**：

1. 美术导出新建筑的整体 GLB 和拆分后的 piece GLB
2. 用 calibrator.html 标定每个 piece 的目标位置（拖动到正确位置）
3. 一键导出 JSON
4. 把 JSON 粘进 `LEVELS[]` 末尾，加上 `pieceNames` / `pieceLore`
5. **完成** —— 新关卡可玩

## 九、组员问答 FAQ

**Q1：为什么不用 React / Vue ?**  
A：mockup 是单文件 HTML，主体 UI 用 PNG 图保留视觉。引入 React 会打乱原视觉风格，且 Three.js 的 imperative API 与 React 的 declarative 范式不太适配。当前架构（vanilla + ES Module）已经足够清晰，且性能更好。

**Q2：MediaPipe 不是要联网吗？**  
A：MediaPipe Hands 模型文件可以下载到本地（约 12MB）。当前我们用 CDN 是为了省构建时间，部署时改为本地引用即可。

**Q3：手势识别在不同光线下表现如何？**  
A：MediaPipe 在自然光、室内灯光下都很稳定；强逆光或纯暗环境精度下降。我们 README 里建议用户在"窗边或室内灯下使用"。

**Q4：第二关比第一关难太多怎么办？**  
A：当前 6 个集合的爆炸位置（dockOverrides）已经经过多轮测试调整。如果未来玩家反馈仍难，可以加一个"新手引导关卡"，或者把第二关拆成 2 个子关。

**Q5：calibrator 是什么时候用的？**  
A：开发期工具，不会出现在最终用户眼前。美术或建筑顾问帮我们做精准标定的"内部 IDE"。可以理解为我们项目的"关卡编辑器"。
