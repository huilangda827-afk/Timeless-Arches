## 作品简介

```
"拾光筑梦"是一个面向中国古代建筑文化传承的 Web 端数字交互平台，以斗拱这一中国木构建筑的核心构件为切入点，包含七大功能模块：

【筑梦】手势识别驱动的 3D 斗拱拼装解谜。用户通过普通摄像头，以拇指食指捏合/张开手势抓取、搬运、拼接斗拱构件。系统采用自研"三阶段磁吸算法"，在远、中、近三个距离段对构件位置、旋转、缩放进行差异化插值，将手势识别的固有抖动吸收到交互体验内，实现高成功率的精确吸附。当前已实现 2 个完整关卡（入门单翘斗拱 + 北京紫禁城御花园万春亭）。

【探微】万春亭斗拱"爆炸图"式部件级解析。加载 6 个组件集合（共 28 个命名部件），一键解体后各集合沿辐射方向动画散开。鼠标悬浮高亮整个集合，单击弹出中文部件名（如撩檐榑、琴面昂、交互斗等）及力学/装饰解析，让用户直观理解"栌斗→拱→昂→枋→檐"的力流传导路径。

【鉴赏】9 栋横跨唐代至清代、覆盖皇宫/官署/民居/公共建筑四大类别的真实古建三维模型，支持 360° 鼠标拖拽旋转、滚轮缩放、右键平移，配合建筑背景、斗拱特点、实景与结构图等文化解析。

【万象图鉴】全部古建的总目录，支持按建筑名、朝代、地区关键词搜索，页面可滚动浏览。

【古建舆图】中国地图上标注 9 个金色脉冲点位，按地理位置导航至对应建筑的鉴赏页面。

【藏阁】已收藏构件的"CS 仓库"式展示模式，模型居中显示，鼠标移动带动模型双轴跟随旋转，滚轮缩放，双击复位。

【门户首页】古风米黄视觉设计，五大功能卡一键导航。

整站基于 Vite + Three.js + MediaPipe Hands 构建，无需安装任何软件，无需专用硬件设备，普通笔记本电脑 + 摄像头即可在浏览器中运行，实现零门槛的古建文化数字化传承。
```

## 开源代码与组件使用情况说明

```
本作品使用了以下开源组件，均严格遵守其开源许可协议：

以上开源组件均为工具/引擎层面的基础设施。本作品的核心创新——三阶段磁吸算法、数据驱动 LEVELS 关卡体系、Calibrator 可视化校准工具、探微爆炸图交互、7 大功能模块的设计与实现、全部 9 栋古建三维模型、28 个斗拱部件的中文命名与文化解析——均为团队独立原创。
```

## 作品安装说明

```
【环境要求】
· 操作系统：Windows 10/11、macOS 10.15+ 或 Linux（任何支持 Chrome/Edge 的系统）
· 浏览器：Chrome 100+ 或 Edge 100+（需支持 WebGL 2.0）
· Node.js：v18.0 或以上（仅开发/构建时需要）
· 摄像头：任意 USB 或内置摄像头（仅"筑梦"手势模式需要）

【安装与运行步骤】
1. 解压源代码压缩包
2. 进入项目目录：
   cd 游戏逻辑与控制/three-scene
3. 安装依赖：
   npm install
4. 启动开发服务器：
   npm run dev
5. 浏览器自动打开 http://localhost:5173/
   · 首页即为门户导航页
   · 点击"筑梦"进入手势拼装游戏（需授权摄像头）
   · 点击"鉴赏"查看 9 栋古建 3D 模型
   · 点击"探微"查看万春亭爆炸图

【生产部署】
1. 执行构建：npm run build
2. 将生成的 dist/ 文件夹上传至任意静态托管平台（Netlify / Vercel / GitHub Pages）
3. 访问部署后的 URL 即可使用，无需后端服务器

【注意事项】
· 首次加载"筑梦"关卡时需下载 GLB 模型文件（约 20-80MB），建议使用稳定网络
· 手势识别功能需要浏览器授权摄像头访问权限
· 建议在室内灯光环境下使用，强逆光或纯暗环境会降低手势识别精度
```

## 设计思路

```
本作品的设计思路围绕"如何让抽象的古建斗拱知识变得可感知、可操作、可记忆"展开，构建了"看→懂→做"三层递进的交互体验架构：

第一层【看】—— 鉴赏模式
解决"看不到"的问题。9 栋真实古建三维模型覆盖唐至清 1200 年跨度，涵盖皇宫、官署、民居、公共建筑四大类别。用户可 360° 自由观察建筑外观与斗拱细节，配合文字解析建立宏观认知。

第二层【懂】—— 探微模式
解决"看不懂"的问题。以万春亭为标杆，将整体斗拱拆分为 6 个功能集合（共 28 个命名部件）。爆炸图式交互让用户逐层下钻，理解每个部件的名称、位置和力学作用，建立从"栌斗"到"撩檐榑"的完整力流认知。

第三层【做】—— 筑梦模式
解决"摸不着"的问题。用户通过真实的手势（捏合抓取、移动搬运、松开释放）亲手拼装每一根构件。身体记忆远比阅读记忆深刻——当你用自己的手把一根"琴面昂"卡进"交互斗"的那一刻，你对杠杆受力的理解将超越任何课本。

技术层面，整站采用纯前端架构（Vite + Three.js + MediaPipe），无需后端服务器，无需安装应用，打开浏览器即可体验。这一设计决策的核心考量是"零门槛传播"——让偏远地区的中学生也能用普通电脑感受紫禁城万春亭的木构智慧。

美术层面，全站采用中国传统色系（米黄、朱红、鎏金、青灰），辅以古风排版（宋体/楷体字族、竖排标题、印章元素），在数字化载体上延续中式审美。
```

## 设计重点难点

```
【重点一】手势识别的精度与交互体验的矛盾
MediaPipe Hands 在浏览器端的手部关键点检测存在 ±2-5 像素的固有抖动，直接映射到 3D 空间后，用户几乎无法将构件精确放置到目标位置。
解决方案：自研"三阶段磁吸算法"。远距离（>1.5m）完全跟随光标，让用户自由把玩；中距离（0.2-1.5m）位置/旋转/缩放向目标 smoothstep 插值，营造"磁力吸引"体感；近距离（<0.2m）直接锁定到目标，松手即吸附。该算法将手势的宏观抖动吸收到了交互体验内——用户越靠近目标，抖动影响越小。

【重点二】多关卡扩展的工程可持续性
每个新建筑关卡需要标定每根构件的精确目标位置（XYZ + 四元数旋转 + 缩放），手工填写 JSON 几乎不可能。
解决方案：设计数据驱动的 LEVELS 关卡配置体系 + 自研 Calibrator 可视化校准工具。美术师在浏览器中拖动构件到正确位置，一键导出 JSON，粘贴到代码中即完成新关卡上线。实现了"加新关卡不改代码"的工程目标。

【难点一】万春亭 6 集合 GLB 的同屏加载与交互性能
万春亭第二关同时加载 6 个组件集合 GLB + 背景环境 + 成品展示模型，模型面片总量极大。早期版本在"提示高亮"时克隆整个 GLB 导致严重卡顿（帧率降至 10 FPS 以下）。
解决方案：将提示特效从"整模型克隆"改为简单 RingGeometry（24 面片 vs 数千面片）；禁用大型静态模型的阴影投射；降低光标拖尾粒子密度。优化后帧率稳定在 55-60 FPS。

【难点二】构件初始角度与目标角度差异导致的吸附失败
万春亭部分构件在备料架上的初始旋转（四元数）与目标位置的旋转差异超过 90°，导致释放时角度判定失败。
解决方案：在三阶段磁吸的中距离段加入四元数 slerp 插值，构件在接近目标的过程中自动预对齐旋转。到达近距离段时旋转已与目标一致，彻底消除角度不匹配问题。

【难点三】门户与游戏的架构隔离
门户首页（mockup 改造，32MB base64 PNG）与筑梦游戏（3600 行 Three.js + MediaPipe）功能差异巨大，混在同一页面会导致内存占用过高和加载缓慢。
解决方案：采用 Vite multi-page 架构，index.html（门户）与 forge.html（筑梦）独立入口，共享 public/ 静态资源池。鉴赏/探微浮层使用独立的 Three.js 实例，与主游戏场景完全隔离。
```
